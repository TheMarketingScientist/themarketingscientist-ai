# Repository Instructions

## Purpose and branch roles

This repository publishes the article section of **The Marketing Scientist** website.

- `GH_Pages` is the source branch for article QMD files, source images, Quarto configuration, the article generator, and the tracked generated article output under `_site/`.
- `gh-pages` is the deployment branch. It also contains the manually maintained homepage at `index.html`.
- The homepage is intentionally not generated by Quarto and must remain manually maintained on `gh-pages`.

### Homepage protection

- **Never modify, regenerate, delete, replace, or overwrite `gh-pages:index.html`.**
- Do not migrate the homepage to Quarto.
- Article publication must deploy article output without replacing the deployment branch's homepage.
- Do not switch to or edit `gh-pages` as part of the article-generation workflow.

## Source and generated paths

- Article sources: `articles/*.qmd` (direct children only).
- Article generator: `articles/generate_articles.py`.
- Publication entry point: `publish_article.ps1`.
- Source and rendered-output validator: `scripts/article_validator.py`.
- Validator tests: `tests/test_article_validator.py`.
- Article-index template: `articles.qmd`.
- Source images: `images/**`.
- Article styles: `article.css` and `style.css`.
- Quarto configuration: `_quarto.yml`.
- Generated article output: `_site/articles.html`, `_site/articles/**`, `_site/articles_files/**`, and `_site/images/**`.
- Other deployable generated resources may include `_site/article.css`, `_site/style.css`, and `_site/CNAME`.
- Ignored Quarto state: `.quarto/**`.

## Automation architecture

- `publish_article.ps1` is the thin Windows orchestration and Git-safety layer. It verifies the repository root, exact `GH_Pages` branch, tools, staged and unrelated changes; consumes validator JSON; invokes the existing generator only after source validation; checks post-generation Git state; and stops before staging.
- `scripts/article_validator.py` owns QMD inspection, metadata and image validation, Editorial/Computational classification, rendered HTML/CSS/link/math validation, deployable local-image synchronization, and `articles.qmd` restoration checks. It never rewrites article QMD content.
- `tests/test_article_validator.py` uses `unittest` and temporary directories outside the repository for parser and rendered-artifact fixtures.

The validator exposes three JSON-producing modes:

```powershell
python -B scripts/article_validator.py classify --repo-root . --article articles/my-new-article.qmd
python -B scripts/article_validator.py source --repo-root . --article articles/my-new-article.qmd
python -B scripts/article_validator.py rendered --repo-root . --article articles/my-new-article.qmd --template-sha256 <sha256>
```

Every mode returns `status`, `classification`, `errors`, `warnings`, `source_images`, `generated_assets`, `expected_article_slug`, and `detected_executable_indicators`. Exit code `0` means validation passed; any nonzero exit means a hard validation failure. Warnings do not change a successful exit code. The PowerShell entry point is the supported publication command; do not invoke rendered validation with image synchronization as a substitute for the guarded workflow.

## Article naming and YAML conventions

Use a lowercase ASCII filename containing only letters, numbers, and single hyphens:

```text
articles/my-new-article.qmd
```

The filename stem is the article slug and must match the generated HTML filename. Do not use spaces, underscores, uppercase letters, punctuation, or non-ASCII characters in the filename.

Every publishable article must begin with valid YAML front matter containing these fields:

```yaml
---
title: "Article title"
author: Andres Acosta
date: 2026-07-15
image: ../images/article-featured-image.png
description: A concise article description.
featured: true
format:
  html:
    theme: cosmo
    css: ../article.css
    execute:
      allow-errors: false
      echo: false
      eval: true
      warning: false
      message: false
      freeze: auto
      pandoc-options: ["--wrap=none"]
execute:
  enabled: true
---
```

Required conventions:

- `title`, `author`, `image`, and `description` must be non-empty.
- `date` must be a real calendar date written exactly as `YYYY-MM-DD`.
- `featured` must be the YAML boolean `true` for the article to appear in the generated article index.
- `image` must resolve from the article file to a file under the repository's `images/` directory. Existing articles use `../images/<filename>`.
- Markdown and HTML body images must also be local files under `images/` and referenced relative to the article QMD.
- Use the existing raw HTML site header and LinkedIn footer conventions unless the user explicitly requests a template change.
- Categories and tags are not currently implemented or required.

## Rich Quarto content

Articles may use Quarto/Pandoc content features, including:

- inline math written as `$...$` and display math written as `$$...$$`;
- Markdown or raw HTML tables;
- blockquotes, footnotes, and citations;
- raw HTML and fenced code blocks;
- Quarto fenced divs and spans, callouts, figure attributes, captions, and layout syntax.

Validation is inspection-only. The publication wrapper must never rewrite, reformat, normalize, or make stylistic or editorial changes to an article QMD. It excludes fenced code, inline code, and HTML `pre`, `code`, `script`, and `style` regions from image and math discovery so that examples are not mistaken for article assets or executable content.

Do not validate math by counting dollar signs. Dollar signs may represent prices, escaped text, or code. Source inspection only identifies likely standard Pandoc math spans; Quarto rendering is the authoritative syntax check. When likely math exists, rendered-output validation looks for math markup or MathJax/KaTeX support. An inconclusive markup check is a warning requiring visual review, not an automatic failure.

## Body image syntax and restrictions

The validator supports these local image forms without treating attributes, captions, titles, or dimensions as part of the path:

```markdown
![Alt text](../images/file.png)
![Alt text](../images/file.png){width=80% fig-align="center"}
![Alt text][figure-id]

[figure-id]: ../images/file.png

<img src="../images/file.png">
```

Collapsed and shortcut Markdown image references and quoted or unquoted HTML `src` attributes are also inspected. Every discovered source path is resolved relative to the article, must remain inside `images/**`, and must exist. After rendering, its matching asset must exist under `_site/images/**`, match the source file, and be referenced by the generated article HTML at a valid deployable path.

Remote image URLs, protocol-relative URLs, and `data:` URIs are intentionally unsupported. Other URI schemes are also rejected. Downloading, embedding, licensing, availability, and content integrity are outside the present workflow, so use a checked-in local asset under `images/**` instead.

## Editorial and Computational articles

The wrapper classifies each article before generation:

- **Editorial**: no executable cell or notebook execution requirement was detected. Ordinary non-executable fenced code is allowed. Editorial articles continue through the existing `quarto render --no-execute` generator.
- **Computational**: an executable Quarto cell (including common `{python}` and `{r}` fences) or a notebook execution requirement was detected. The wrapper lists every detected execution indicator and stops before generation.

Engine declarations such as `jupyter: python3`, `knitr`, or `engine` are reported, but a declaration alone does not make a body with no executable cell Computational. An explicit notebook-backed requirement such as an `.ipynb` value is treated as Computational.

**Code execution always requires explicit user authorization.** Do not silently alter the generator, remove `--no-execute`, start a kernel, execute a notebook, or run article code. A Computational article requires a separately reviewed and explicitly authorized execution workflow before generation or publication.

## Source validation and rendered-output validation

Source validation happens before the generator and produces hard failures only for reliable conditions: invalid required YAML, unsafe or missing local image paths, undefined image references, unclosed image destinations, unclosed fenced code, disallowed Git state, or Computational content. It does not serve as a general Markdown style checker.

Rendered-output validation happens only after an authorized future generator run. Missing required pages, article-index links, local images, or local stylesheets are failures. Math support and local link/anchor checks can be inherently ambiguous: an inconclusive math check or a link supplied separately by the manually maintained deployment branch is reported as a warning. Warnings must be reviewed, but they are distinguished from conditions that make the deployable output definitely incomplete.

## Generation and safe publication command

Run generation from the repository root only:

```powershell
python articles/generate_articles.py
```

For a new article, use the guarded publication wrapper instead of invoking the generator directly:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish_article.ps1 -ArticlePath .\articles\my-new-article.qmd
```

The wrapper validates the source, classifies it as Editorial or Computational, runs the existing generator only for Editorial content, ensures required local images are copied into deployable `_site/images/`, verifies the generated listing and article page, and reports the prospective staging set. It never stages, commits, pushes, changes branches, rewrites QMD content, or executes article code.

Run non-mutating validator QA with bytecode writing disabled:

```powershell
python -B -m unittest discover -s tests -p "test_article_validator.py" -v
python -B -c "from pathlib import Path; [compile(Path(p).read_text(encoding='utf-8'), p, 'exec') for p in ('scripts/article_validator.py', 'tests/test_article_validator.py')]"
```

## Expected generation changes

`articles/generate_articles.py` performs the following operations:

1. Temporarily creates `articles.qmd.bak` and expands the `{{featured_articles}}` placeholder in `articles.qmd`.
2. Deletes and recreates `_site/articles/`.
3. Runs `quarto render --no-execute`.
4. Restores the original `articles.qmd`; `articles.qmd.bak` should not remain after success.

A valid generation may change or recreate:

- `_site/articles.html`
- `_site/articles/*.html`
- `_site/articles/*_files/**`
- `_site/articles_files/**`
- `_site/images/**`
- `_site/article.css`
- `_site/style.css`
- `_site/CNAME`
- ignored `.quarto/**`

The safe wrapper may copy featured and local body source images from `images/**` to `_site/images/**` when Quarto did not copy them. It must verify the copied bytes, must not rewrite the generated HTML to hide invalid paths, and must not leave a changed `articles.qmd` or an `articles.qmd.bak` file.

## Required checks before publication

Before considering an article ready to stage:

1. Confirm the current branch is exactly `GH_Pages`.
2. Confirm there are no staged files and no unrelated unstaged or untracked changes.
3. Confirm the article is a direct child of `articles/` and follows the filename convention.
4. Parse the YAML and validate every required field and its type/value.
5. Confirm the date uses `YYYY-MM-DD` and is a valid calendar date.
6. Confirm the featured image and every local body image exist under `images/`, including inline, attributed, reference-style, and HTML image syntax.
7. Classify the article. Stop on Computational content, list the indicators, and obtain explicit user authorization before any separately designed code-execution workflow.
8. For an Editorial article, run `python articles/generate_articles.py` from the repository root and treat any nonzero exit or reported error as failure.
9. Confirm `_site/articles.html` exists.
10. Confirm `_site/articles/<slug>.html` exists and is linked from `_site/articles.html`.
11. Confirm every featured image and local body image exists in deployable output, matches its source image, and is referenced by generated HTML at that deployed path.
12. Confirm `article.css` and every other local stylesheet referenced by the generated article exist in `_site/**`.
13. Check local links and anchors where practical. Treat separately deployed homepage links and otherwise inconclusive checks as warnings rather than false failures.
14. If source math was detected, confirm rendered math markup or MathJax/KaTeX support; warn and require visual inspection if the result is inconclusive.
15. Confirm no `articles.qmd.bak` remains and `articles.qmd` was restored byte-for-byte.
16. Confirm generation changed only the intended article, its referenced source images, and `_site/**`.
17. Review every warning, `git status --short`, `git diff --stat`, and the exact prospective staging list.
18. Inspect the rendered pages locally before requesting permission to stage or publish.

## Git safety

- **Never run `git add`, `git commit`, or `git push` without explicit user approval.**
- Never force-push either branch.
- Never merge, reset, or switch branches as part of publication unless the user separately authorizes it.
- Never include unrelated existing changes in an article publication.
- The publication script must stop after reporting which files would be staged.
- Deployment and workflow changes require a separate, explicit task; do not change `.github/workflows/**` during ordinary article publication.
